# LookMatch checkpoint

OBJECTIVE — iPhone web app that copies a reference photo's look onto other photos by measuring each photo and solving slider values per photo; Shawn can create presets, batch-match, tweak, and export JPEG + Lightroom files to Google Drive from his iPhone 15 Pro Max (iOS 26.6.1).

DECIDED
- No Mac → static web app (Safari / home screen), not native. Engine is plain JS shared by browser workers and Node test tools.
- Repo: github.com/shawnzebley/lookmatch (renamed from "Lookmatch" to lowercase). Site served by GitHub Pages from branch `gh-pages` (= `web/` folder via `git subtree split --prefix web -b gh-pages`, force-pushed). Live URL: https://shawnzebley.github.io/lookmatch/
- Google OAuth client ID (baked in as default in web/app.js): 243038152226-jfgss8uq68lb72bi9j5jqgkdlg475kj8.apps.googleusercontent.com, project project-b4125537-0627-4305-b6c. Registered JS origin https://shawnzebley.github.io ; redirect URI https://shawnzebley.github.io/lookmatch (no trailing slash — app sends it that way on purpose; Pages 301s to /lookmatch/ and keeps the #access_token).
- Drive auth: OAuth implicit token redirect flow, scope drive.file, token lasts 1 hour, sign-in reloads the page. Exports go to Drive › LookMatch › "<preset> <date>"; preset backups to Drive › LookMatch › presets.
- Presets store measured stats + thumbnail, never slider values. Solver: staged bounded Levenberg–Marquardt (tone → WB → color → touch-up) on a 512 px preview; full-res applied via 33³ LUT, tiled (≤4 MP tiles) for iOS canvas limit; JPEG encode with jpeg-js (1.5 s at 24 MP in Node vs 4 s mozjpeg).
- Guards: clipping cap = max(orig, ref) + 0.1%, near-white crowding penalty, curve slope ≤ 2.2, skin hue window 35–64° (Lab) and ±6° drift, lit-skin chroma ≥ 0.75×, adjacent-HSL-band smoothness (6× on red/orange/yellow), sat/vib opposite-sign penalty, final scale-back guard.
- Brightness pull 0.5 toward ref median, reduced for low-key photos (night stays dark).
- Lightroom export: `_lightroom.jpg` = original + embedded crs XMP; `_lookmatch.xmp` = develop preset; modes "sliders" (default) or "curve".
- RAW: later.
- Layout (2026-09-27c, Shawn: "Select a photo, add the photographer's styling to it or select a reference to mimic"): Edit tab is home: step 1 Photos (big Select button, then a horizontal strip + status line), step 2 Style (segmented Photographer | Reference photo; photographer cards with plain-words summary from style-data medians + shadow/mid/highlight dots; reference cards + '+ Reference photo' + 'Import Lightroom preset'). Tabs: Edit / References (old Presets list) / Settings. Header shows 'Export all N'. A look = {kind:'photographer',key} | {kind:'preset',id}; S.look (localStorage lm_look) applies to all photos, p.look overrides one photo from the editor's Style card; 'Use this style on all photos' copies it back. Photographer-only solve = solvePreset(ps, o, {}, pull 0.25) + fitFinish. One photo + style picked -> editor opens by itself. Re-match button renamed Redo.
- Editor (2026-09-28): photo fills the screen (flex, no page scroll); controls are a short bottom panel (30dvh, clamp 160-320px) with tab chips + a horizontal scroll-snap pager: Look / Subject / Light / Color / Retouch / More. Pinch or wheel zooms the canvas (CSS transform, up to 8x), double-click toggles 3x, Fit button resets; one finger pans when zoomed (split line is grabbed within 32px); preview re-renders at 2400 px once zoomed past 1.4x. Tool taps (heal, point, mask) fire on release so a pinch never lands one. Hold on photo in After mode shows Before.
- Crop + level (engine/geom.js): geom = {angle (deg, + = photo turned clockwise), x,y,w,h as fractions in the turned W x H frame}; worker crops before measuring, so solve + loss checks see only the crop; export renders the crop at full res; Lightroom gets HasCrop/CropTop/Left/Bottom/Right/CropAngle (= -angle, per Adobe forum SDK note; EXIF orientation 1/3/6/8 mapped). Aspect chips as labelled (4:5 = portrait), ⇄ flips. Auto level = strongest near-axis edge direction within ±20°.
- HEIF/HEIC/HIF: native createImageBitmap first (with, then without, orientation option); on failure + HEIF brand, libheif-js 1.23 (web/vendor/libheif, LGPL, lazy import) decodes, then the worker keeps a q97 JPEG (e.file) and the original (e.orig) for EXIF. No _lightroom.jpg for HEIF originals (not JPEG).
- Problem log: every upload/match/crop failure goes to localStorage lm_errors (last 20) with step, file name/type/size, message, stack, UA; tile error sheet + Settings > Recent problems have Copy details.
- Photographer finish = "what would X do to this photo": engine/style.js signature (p50, spread, hue-sector shares, neutral, top brightness, skin) -> k nearest of the photographer's published images (style-data.js rows from tools/style_records.py) -> targets p1/p99/chroma/shadow/mid/highlight Lab; fitFinish moves 50% of the gap (35% on medians-only profiles) x Style strength, on the colour-grading WHEELS (added to the match's grade, each wheel ≤20 units/axis, zones without a target held), plus finishSat, skin hue held ±4°, no new clipped colour. Finish Lab tint sliders removed from UI (compile still reads them). Wheels UI: 3 wheels, sqrt sat scale, faint dot = match's grade, dashed line = finish move; "What X would do here" card lists moves.
- Subject / background (2026-09-27d, Shawn: "mask the subject and edit separately from the background"; chose people auto + tap for anything else, and auto split + his own tweaks):
  - Masks (web/segment.js, in the worker): MediaPipe Selfie Multiclass 256 (16 MB, people = not background) on a 512 px copy, second pass on a padded crop when people fill < 45% of the frame; Magic Touch (InteractiveSegmenterLegacy, 6 MB, lazy) = object under a tap, added (max) or removed (multiply). Guided filter (r ~10 px then ~3 px at 1024) + stretch (q-0.3)/0.4. Stored at 1024 long side in whole-photo coords (e.mask: person, picks, useAuto, sub, ver); drawn through drawTransform for crop/level, previews and export tiles. web/mp.js re-sets self.ModuleFactory before each MediaPipe task create (one create at a time), else the 2nd task in a worker fails with 'ModuleFactory not set'.
  - params.local = { subject: {...}, background: {...} }: amounts added on top of the whole-photo sliders (exposure, contrast, highlights, shadows, whites, blacks, temp, tint, saturation, vibrance) + three local wheels added in Lab. processPixelSet mixes the two regions per pixel by ps.subject; render = two LUTs mixed by the mask (applyLUTMasked).
  - Style split (engine/regions.js, after the match and the finish): relations sep (subject minus background median L*), dA/dB (tint of each region's lower-chroma half), logC (ln chroma ratio). Want = reference's own stats.regions, or the photographer's k nearest published photos with a person (nearestRegions, rows need rSep). Move 0.4 x strength, capped per photo at sep 6 L*, tint 3, logC 0.22; subject-darkening moves x0.35, subject-dulling x0.5. Fitted with local exposure (cap 0.5 EV), temp (25), tint (20), saturation (30) per region; whole-photo mean L/tint/chroma held; region exposures <= 0.7 EV apart (halos); skin hue +-4 deg; no new clipping. Regions count only mask >= 191 (subject) / < 64 (background); usable when subject is 3-92% of frame.
  - Editor: 'Subject and background' card under Style: Whole photo / Subject / Background tabs (region tabs swap the slider card to local sliders and the wheels to local wheels, and flash the region red for 1.3 s), + Add / - Remove (tap the photo), Undo, Show, 'People count as the subject', 'Style sets the subject apart from the background' (p.split), and a list of what the split did. A mask change re-runs the style unless sliders were hand-tuned.
  - Old references get stats.regions measured once from their saved thumbnail (ensurePresetRegions).
  - Lightroom export: each region with local amounts = a MaskGroupBasedCorrections entry with a Select Subject mask (What=Mask/Image, MaskSubType 1; inverted for background). Local values -1..1, exposure = stops/4 (from Cvatik 2018 .lrtemplate local corrections: brush saturation -0.16 = -16), vibrance folded into LocalSaturation, three wheels -> one LocalToningHue/Saturation. MaskSubType values from blog.otakugard.moe (0 background, 1 subject, 2 sky, 3 people). Not checked in real Lightroom.
- Loss check (engine/loss.js): blown ≥0.3% warn / ≥1.5% bad, crushed 0.5/2, clipped color 1/4, lost detail (flattened L* gradient) 2/6, banding curve slope 2.6/3.4. Culprits = sliders changed from the auto match, reverted one at a time. Clipping overlay: red blown, blue crushed, amber clipped color, dim = already in original; turns on automatically the first time an edit goes 'bad'.
